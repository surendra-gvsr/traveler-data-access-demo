test in `tests/`, and the spec is the thing that gets changed first when behaviour
changes.

## The one idea behind all five

Every component here fails in the same way if you get it wrong: **it silently returns a
number that looks fine.** A double-counted search, a stale destination, a feature that
peeked at the future, a profile served after consent was withdrawn — none of these raise
an exception. They all produce plausible output.

So the design rule throughout is to make the dangerous thing structurally impossible
rather than merely discouraged: dedupe by primary-key insert instead of check-then-write,
guard last-write-wins fields with a version comparison, filter features on knowledge time
as well as valid time, and route every read through one function that cannot be bypassed.
Where that is not achievable, add an assertion that turns a silent leak into a loud test
failure.

## Vocabulary

Two clocks matter throughout, and conflating them is the root cause of most of the bugs
these specs exist to prevent:

- **`occurred_at`** — *valid time*. When the thing happened in the traveler's world.
- **`ingested_at`** — *knowledge time*. When our platform first learned about it.

A feature computed "as of" a timestamp is only honest if it filters on **both**.

- **`source_version`** — a per-traveler monotonic counter stamped by the upstream system
  when the event was produced. The ordering token for last-write-wins fields. Delivery
  order cannot change it, which is exactly why it is trustworthy and why wall-clock
  arrival time is not.
- **Consent** is event-sourced, not configured. It arrives on the same unordered stream
  as everything else, which makes "don't let a replayed opt-in override a newer opt-out"
  a correctness requirement rather than a policy aspiration.

## Non-goals

- Not a recommender. Profiles are descriptive aggregates, not predictions.
- Not multi-tenant, not distributed, not tuned for scale. Single-process SQLite is
  deliberate: the governance properties are the point, not the throughput.
- No real traveler data, ever. Everything here is generated by `generate.py`.
